타이핑을 '확인'까지 미루던 동작을 바꿨다. 입력창의 기존 onChanging/onChange를 그대로 불러 치는 대로 미리보기하고, 반영한 글은 확정값으로 기억한다. 확인 때는 아직 반영되지 않은 입력(onChange만 있어 포커스를 옮기기 전인 숫자 칸 등)만 기존 검증 경로로 한 번 더 반영한다. 다른 옵션의 미리보기가 아직 반영되지 않은 원문을 덮지 않는 것, Enter·IME·여러 줄 처리, 숨김·꺼짐 입력 보호는 그대로다. 폼 틀 스크립트 17개의 글 입력은 onChanging에도 같은 처리기를 걸어 글자마다 반영한다. 아래 본문은 처음(미루기) 설계 기록이다.

## 원인과 수정

입력창 onChanging/onChange가 값 갱신과 미리보기 생성·이동을 함께 수행했다. 일부 확인 경로는 이미 갱신된 옵션 객체를 읽어, 포커스가 남아 onChange가 발생하지 않은 입력을 누락할 수 있었다.

공통 `ui_tab_helper.jsxinc`에서 입력창의 원문과 마지막 반영값을 분리한다. 타이핑과 blur는 원문을 유지하고 기존 콜백을 실행하지 않는다. 확인·완료 버튼에서 변경된 활성 입력창의 원문을 먼저 수집하고 기존 onChange(없으면 onChanging) 검증 함수를 호출한 뒤 기존 확인 동작을 실행한다. 숫자의 범위·반올림·잘못된 값 복원은 각 스크립트의 기존 규칙을 유지한다. 확인 시 여러 기존 검증 콜백이 렌더링할 수 있으므로 렌더링 횟수를 단 한 번으로 합치는 변경은 아니다.

슬라이더·R·다른 옵션 버튼은 기존 동작을 유지하며, 실행 중에는 확정된 텍스트만 읽도록 하고 아직 입력 중인 원문을 뒤에 복원한다. Enter는 네이티브 입력 확정에 맡기고 preventDefault/stopPropagation을 호출하지 않는다. 기본 실행 버튼(defaultElement)을 null로 두어 Enter가 완료 버튼을 실행하지 않게 하며, Enter 직후 확인하면 원문을 반영한다. 여러 줄 입력과 wantReturn의 줄바꿈, 한글 IME 확정, Escape·방향키는 가로채지 않는다. Tab 이동도 isComposing/keyCode 229 이벤트는 그대로 전달한다. 실제 macOS 한글 IME 타이핑은 아직 검증하지 못했다.

확인 버튼은 문구 덮어쓰기 전 name=ok 또는 기존 확인/완료/완료하기/적용/실행/만들기/그리기/OK로 식별한다. 기존 UI 순서·저장 키·설정 포맷은 바꾸지 않는다. 공통 헬퍼가 없던 `숫자 순서 만들기.jsx`와 `개체 바꾸기.jsx`에 로더·바인딩만 추가했다. 공통 헬퍼를 읽지 못하는 환경에서는 기존 동작으로 돌아간다.

- Enter 직후 포커스 이동 없이 완료한 경우: 버튼 래퍼의 flush가 각 input.text를 직접 읽고, 기존 onChange(없으면 onChanging) 검증 후 기존 완료 콜백을 호출한다. 네이티브 Enter가 onChange를 보내는 경우/보내지 않는 경우 모두 최신 문자열과 숫자가 저장되는 모의 검사를 추가했고 통과했다. 포커스 이동 이벤트나 Enter 기본 동작에 의존하지 않는다.
- 여러 줄 Enter·한글 IME Enter에는 preventDefault/stopPropagation을 호출하지 않는다. 실제 키 입력/조합기의 동작은 앱 실기 검증 전이다.
- 기준 HEAD e0ea7297517a64e29a0a2518c81514c64e88d480을 git archive로 /tmp의 별도 디렉터리에 풀어 기존 실패 4개를 실행했다. 현재 트리와 모두 종료 코드 1 및 동일한 실패 로그였다(저장소 경로와 macOS /private/tmp 별칭만 정규화). check-arrowhead-shapes: 파동.jsx shape dropdown, check-crystal-sizes: foldPanel undefined, check-math-heads: 공통수학.jsx shape dropdown, check-script-safety: 기존 역학 코일 스프링 토큰 누락. 비교 로그 및 JSON: /tmp/illu-dialog-input-test/head-comparison.json.
- AIHangMonitor 차단 근거는 프로브의 휴리스틱이다: CPU가 8% 미만으로 떨어지지 않은 대기 뒤 1초 sample에서 AIHangMonitor 스레드의 mach_continuous_time/clock_gettime 표본 합계가 200을 넘으면 exit 2로 osascript 요청 전에 중단한다. 실제 표본 파일은 프로브가 삭제하므로 정확한 측정값·근본 원인은 확보하지 못했다. 이후 사용자가 명시적으로 강제 종료를 요청하여, /Applications/Adobe Illustrator (Beta)/Adobe Illustrator.app/Contents/MacOS/Adobe Illustrator(PID 404)만 SIGKILL로 종료하고 해당 PID 및 Illustrator 실행 파일 프로세스 부재를 확인했다. 다른 Adobe 앱 종료와 재실행은 하지 않았다. 이후 검사는 정적·모의 검사만 수행했다. 실제 앱 검증을 다시 하려면 사용자가 Illustrator를 열고 별도 임시 문서를 준비하는 것이 다음 최소 조치다.
